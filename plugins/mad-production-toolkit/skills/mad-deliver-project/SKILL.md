# MAD project delivery

Keep the final picture, lossless mix, editable intermediates, and release package distinct. Choose the intended release destination and record its project-specific loudness target and true-peak ceiling before QA. Locate this installed skill's absolute directory, then run `python3 <skill-directory>/scripts/deliver.py --help`; use that absolute script path for every command below.

1. If the approved timeline includes a silent outro, run `append-outro --song-video SONG.mp4 --outro-video CARD.mp4 --mix-audio MIX.flac --output FINAL.mp4`. The song picture must have a constant frame rate. The mix must cover the whole song; the tool rejects a short mix and trims at the song boundary before padding silence over the card. The default maximum excess mix duration is 0.02 seconds (`--mix-tolerance`). It normalizes the card to the song's frame rate and size, then verifies total frames. If there is no outro, use the approved song video as `FINAL.mp4` in the remaining steps.
2. Run `qa --video FINAL.mp4 --expect-frames N --report qa.json`. It checks the expected frame count, stream timing, and complete decoding, and **measures** integrated loudness and true peak. It does not normalize sound or enforce a loudness target. Compare the reported values with the recorded project/destination target; silence or an unacceptable value can still produce a successful command exit. It accepts exactly one video and at most one audio stream; a silent card needs `--allow-silent`. The default audio/video stream timing tolerance is 0.05 seconds (`--av-tolerance`) to accommodate encoder padding. Watch and listen to the complete result as well as representative cuts and lyric/title frames.
3. Freeze one approved pair: `FINAL.mp4` and the exact `MIX.flac` version used for that picture. Record their paths, QA report, target comparison, and hashes in the private project release notes; any change to either file restarts QA and packaging. Run `bundle --config bundle.json --output-dir PROJECT_BUNDLE` with that same pair if they are part of the authorized bundle. Each listed item needs a declared rights status and permission reference; the tool checks these fields but cannot verify underlying permission. Use the [schema](references/bundle.schema.json) and [fictional example](references/bundle.example.json). The bundle manifest has relative paths and SHA-256, with no original local paths. Do not include an asset whose reuse or redistribution has not been confirmed for the intended delivery.
4. Run `zip --video FINAL.mp4 --audio MIX.flac --output DELIVERY.zip` using the frozen pair. Compare the video's bundle-manifest SHA-256 with `qa.json`, and compare both ZIP member hashes with the matching bundle-manifest records before handing off; the ZIP command itself only verifies each member against its supplied input file. [The release check](references/release-check.md) gives a portable comparison command and the human decision fields. If the recipient does not need an asset bundle, record the same hashes in the private release notes instead. These checks establish file identity and integrity, not mix alignment, decodability, or redistribution rights.

The tool reads local media only. It does not infer license permission from public availability, retrieve footage, choose visual design, or silently alter an existing bundle asset. Requires Python 3.10+ and FFmpeg/FFprobe with H.264 encoding.
